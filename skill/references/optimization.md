# Improvement proposals

Prioritize observed gaps in category language, buyer-use-case pages, comparisons, documentation access or supporting sources. Small exploratory panels cannot establish causes.

Each action has an id, evidence ids, hypothesis, proposed change, effort, priority and repeat measurement with supporting and rejecting outcomes. Name unchanged questions and provider profiles. Do not promise content changes will alter recommendations.

Save a proposal and content/patch draft in `drafts/<action-id>/`. Keep app source untouched until requested. Publishing is separate. Preserve the pre-change run and avoid causal conclusions from a before/after observation alone.

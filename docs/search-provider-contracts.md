# Search measurement contracts

Checked against the official pages linked below on 2026-09-24. This is the C00 contract for the implementation plan. It describes the current implementation and the evidence required before a new search profile can be enabled. Documentation review is not account or model verification. No live provider request was made for this contract.

Implementation update, 2026-09-24: the OpenAI Responses route is available by explicit `HEARSAY_OPENAI_SEARCH_POLICY=auto|required` on `gpt-5.6-luna`. Anthropic basic web search is available by explicit `HEARSAY_ANTHROPIC_SEARCH_POLICY=auto` on `claude-sonnet-5`, with three searches and one continuation at most per target. Sanitized request, evidence, usage, quote, and storage fixtures pass; account access has not been checked with a live request. Search-off routes remain the default. Recurring search requires a separate schedule quote and target ceiling. Gemini API search remains gated.

## Common contract

| Policy | Request meaning | Comparable answer rule | Availability at baseline |
|---|---|---|---|
| `off` | No search tool is requested on a documented non-search route. | Complete answers in the exact off series. | Existing OpenAI, Anthropic, and Gemini API behavior; not a label to assign retroactively without a recorded profile. |
| `auto` | A supported search tool is available and the provider may decline it. | Complete answers in the exact auto series. Explicit no-search answers remain in the denominator. | Disabled pending C01-C06. |
| `required` | A supported mechanism asks for search and structured evidence confirms execution. | Complete answers with verified, complete search execution. Other answers remain visible as excluded attempts. | Existing subscription profiles only. API support remains disabled pending provider gates. |
| `legacy` | Historical request settings or evidence cannot be reconstructed fully. | Historical reporting only, with its uncertainty stated. | Required for historical observations, especially Sonar. |

The six surface IDs remain `openai-api`, `anthropic-api`, `gemini-api`, `perplexity-api`, `codex-agent`, and `claude-code-agent`. A series also needs the endpoint family, requested and returned model when available, tool version and options, policy, prompt envelope, supported locale controls, answer limits, benchmark revision, and analysis revision. A changed answer-affecting setting starts a new series. A new question or entity definition starts a new benchmark revision. An unexposed upstream model change remains a limitation even when the returned alias stays the same.

For each logical target, keep the submitted question, search actions and exact exposed queries, returned or fetched sources, final answer citations, and answer interpretation separate. One target can have several attempts or continuations but at most one comparable final answer. Missing query metadata is `unavailable`, never an invented empty query or a reconstruction from the answer. A completed `auto` response can be `not_used` only when the provider's response semantics establish that no search ran. Otherwise absence of an action is `unverified`. A completed search with no results is still a completed search. A failed search after a successful one makes required-policy evidence partial and excludes that answer from comparable metrics.

Each adapter must return a completion state, search state, evidence completeness, query-metadata state, action and source provenance, citation provenance, and usage per known attempt. A refusal, empty answer, truncation, paused turn, transport error, or parser limit is inspectable but not comparable. Counts distinguish attempted, complete, comparable, verified-search, and query-exposed answers. Source and citation totals never stand in for one another. The API may return usage for a failed or excluded attempt; known usage still counts toward cost.

Account compatibility still needs an opt-in live smoke check. Other proposed API search profiles remain gated. An unsupported model or tool combination returns an actionable error rather than silently using another endpoint or policy.

Existing Chat Completions stays a separate non-search route. | A completed `web_search_call` search action verifies search. Its `action.queries` may be absent. Parse all output items and text parts. | Require a completed final response and nonempty final answer; retain incomplete and failed responses. Record all reported token usage and search calls. The hosted tool has no documented hard per-request search-call ceiling in this contract, so a quote is a forecast, not a hard dollar cap. A switch to the newer Interactions API is a new profile and needs its own parser. | Confirm grounding from structured metadata, not a citation-looking URL in answer text. ## Fixture and release gates

Existing sanitized inputs are `test/fixtures/{openai,anthropic,gemini,perplexity}.json`, `provider-errors.json`, `codex-search.jsonl`, `claude-search.jsonl`, the two rate-limit JSONL files, and `claude-unverified.jsonl`. They test the baseline shapes. New fixtures must cover the following cases before each new route is enabled.

| Route | Minimum fixture cases beyond the baseline |
|---|---|
| OpenAI | Search with and without exposed queries, multiple actions and answer parts, reported source absent from citations, explicit no-search auto, required search missing or incomplete, refusal, failed tool, usage on error. |
| Anthropic | Multiple tool IDs and results, empty success, HTTP 200 tool error, pause then final, continuation cap, cited result different from retrieved result, accumulated usage, missing model access. |
| Gemini | Queries with chunks and supports, chunk without support, no grounding, invalid indices, non-ASCII spans, required suggestions rendered safely, safety stop, endpoint and model mismatch. |
| Perplexity | Two `search_results` and one different `citations` URL, absent query wording, numeric reference mapping, partial usage, failed or truncated choice. |
| Subscription agents | Multiple queries/results for one action, start/completion reconciliation, missing IDs, unknown event type, terminal failure, redaction, size and event limits. |

No credential or account capability was verified through a live request. Live smoke checks remain opt-in, bounded, and outside CI. Gemini API search remains unavailable. The baseline non-search routes and existing subscription runs keep their current behavior.
